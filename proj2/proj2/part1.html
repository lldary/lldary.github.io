Archlab gem5 Project 2

Part 1: Add Branch Predictor in the Configuration Script

In this part, we will configure and build ChampSim with different branch predictors. In ChampSim, branch predictor implementations are located under the branch/ directory.

ChampSim is natively a detailed out-of-order (O3) CPU simulator, so you do not need to manually change the CPU model. To select a specific branch predictor, you can configure the "branch_predictor" field in the build JSON script (lab2_config.json).

ChampSim provides several built-in branch predictors in the branch/ directory. In this part, we will focus on three of them: bimodal, gshare, and hashed_perceptron. You can specify the desired branch predictor in lab2_config.json as follows:

{
  "branch_predictor": "bimodal"
}

(To test gshare or hashed_perceptron, simply change "bimodal" to "gshare" or "hashed_perceptron" in lab2_config.json.)

After updating the JSON file, generate the build files and compile ChampSim:

./config.sh ./lab2_config.json
make -j $(nproc)

Next, let me run the trace files and examine how these branch predictors impact system performance. ChampSim is trace-driven, and trace files are typically stored in *.champsimtrace.xz format. Among the provided workloads, shell_sort and spfa are sensitive to branch predictor performance, while gemm and binary_search are insensitive. In Project 2, you are only required to run the sensitive workloads (shell_sort and spfa).

To test the performance of the bimodal predictor, run the following execution commands:

# Run with the compiled bimodal executable
bin/champsim --warmup-instructions 20000000 --simulation-instructions 100000000 ../trace/shell_sort.champsimtrace.xz
bin/champsim --warmup-instructions 20000000 --simulation-instructions 100000000 ../trace/spfa.champsimtrace.xz

The process for testing gshare and hashed_perceptron is similar: update "branch_predictor" in lab2_config.json, re-compile with ./config.sh and make, and then re-run the trace files using the commands above.

Tip

In this project (Parts 1 to 3), setting --simulation-instructions to 100000000 (1e8) or 200000000 (2e8) is sufficient to clearly observe performance differences among branch predictors while saving simulation time.

After the simulation finishes, ChampSim will output execution statistics directly to the terminal (or stdout log). Pay attention to the following metrics in the summary output:

  • CPU 0 cumulative IPC: Indicates overall processor performance.
  • Branch Prediction Accuracy / MPKI: Reflects conditional branch prediction quality.

If accuracy is not printed directly, you can calculate it using the printed total branch instructions and misprediction counts:

Accuracy=1−Total Conditional BranchesBranch Mispredictions​

Deliverables

Please run the two BP-sensitive workloads (shell_sort and spfa) across all three branch predictors. The remaining workloads (gemm and binary_search) are insensitive to BP; you can run them for extra exploration if interested.

In your report, please include figures or tables showing the Branch Prediction Accuracy, MPKI and CPU IPC for the following combinations:

  • Branch Predictors: bimodal, gshare, hashed_perceptron
  • Traces: shell_sort, spfa
  • Configuration: Default 1-core configuration with no prefetchers
