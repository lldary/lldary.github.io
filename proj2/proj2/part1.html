Archlab ChampSim Project 2

Part 1: Add Branch Predictor in the Configuration Script

In this part, we will configure and build ChampSim with different branch predictors. In ChampSim, branch predictor implementations are located under the branch/ directory.

ChampSim is natively a detailed out-of-order (O3) CPU simulator, so you do not need to manually change the CPU model. To select a specific branch predictor, you can configure the "branch_predictor" field in the build JSON script (lab2_config.json).

Use the course-provided ChampSim package from PKU Disk (the same course drive linked in Project 1). In this part, compare the three baseline predictors under branch/: local_bp, bimodal, and tournament. From the ChampSim root directory, create lab2_config.json with the following configuration:

{
  "executable_name": "champsim",

  "ooo_cpu": [
    {
      "frequency": 4000,

      "rob_size": 352,

      "branch_predictor": "bimodal",
      "btb": "basic_btb",

      "mispredict_penalty": 15
    }
  ]
}

To test local_bp or tournament, change "branch_predictor": "bimodal" to "branch_predictor": "local_bp" or "branch_predictor": "tournament" in lab2_config.json.

After updating the JSON file, generate the build files and compile ChampSim. The configuration selects the predictor used by the executable. The course Makefile may still compile other bundled modules:

./config.sh ./lab2_config.json
make -j $(nproc)

Next, let me run the trace files and examine how these branch predictors impact system performance. ChampSim is trace-driven, and trace files are stored in *.champsimtrace.xz format. The course repository includes shell_sort.champsimtrace.xz and spfa.champsimtrace.xz under traces/; run the commands below from the ChampSim root directory. Among the provided workloads, shell_sort and spfa are sensitive to branch predictor performance, while gemm and binary_search are insensitive. For the manual comparisons in Parts 1 to 3, run shell_sort and spfa.

To test the performance of the bimodal predictor, run the following execution commands:

# Run with the compiled bimodal executable
bin/champsim --warmup-instructions 20000000 --simulation-instructions 100000000 traces/shell_sort.champsimtrace.xz
bin/champsim --warmup-instructions 20000000 --simulation-instructions 100000000 traces/spfa.champsimtrace.xz

The process for testing local_bp and tournament is similar: update "branch_predictor" in lab2_config.json, re-compile with ./config.sh and make, and then re-run the trace files using the commands above.

Tip

For the manual baseline comparisons in Parts 1 to 3, use 20M warmup + 100M simulation instructions for every predictor on both workloads, as in the commands above. Keep all other simulator settings identical across predictors. The separate local evaluation script and leaderboard evaluation use their own evaluation settings.

After simulation, use the final Region of Interest Statistics (ROI), excluding warmup. Following the course ChampSim statistics implementation, let B be the sum of branch counts and M the sum of branch misses across direct jumps, indirect branches, conditional branches, direct calls, indirect calls, and returns. Let I and C be the instruction and cycle counts for the same ROI.

Accuracy (%)=100×(1−BM​)

MPKI=1000×IM​,IPC=CI​

Use the printed overall Branch Prediction Accuracy, MPKI, and CPU 0 cumulative IPC from this ROI summary. These overall branch metrics include all six branch types; the separately printed Branch type MPKI values are per-type breakdowns. Higher Accuracy and IPC are better; lower MPKI is better. Use these definitions throughout Parts 1 to 4.

Deliverables

Please run the two BP-sensitive workloads (shell_sort and spfa) across all three branch predictors. The remaining workloads (gemm and binary_search) are insensitive to BP; you can run them for extra exploration if interested.

In your report, please include figures or tables showing the Branch Prediction Accuracy, MPKI and CPU IPC for the following combinations:

  • Branch Predictors: local_bp, bimodal, tournament
  • Traces: shell_sort, spfa
  • Configuration: Default 1-core configuration with no prefetchers

In total, you need to execute ChampSim six times.
