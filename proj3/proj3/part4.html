Part 4: Crafting a Hard Trace (Cache & Prefetcher Stress Testing)

In this final part, you will flip the perspective from defender (building a prefetcher) to adversary (constructing a cache-hostile memory trace). Your goal is to design a synthetic workload or memory access trace that stresses the cache hierarchy, maximizes cache misses, and fools standard prefetchers (such as Next-Line or Stride prefetchers).

Grading for this part will be determined by the difficulty score of your trace—specifically, how effectively it degrades baseline system performance and challenges hardware prefetching mechanisms.

Trace Generation Overview

ChampSim traces (.champsimtrace.xz) capture dynamic execution streams, including instruction PCs, register usage, branch directions, and memory access addresses.

You can generate your custom trace in the below way:

Benchmark C Code + Tracer: Write a custom C/C++ program (e.g., stress_test.c) that implements cache-unfriendly access patterns (e.g., prime-strided array traversals, pointer chasing through randomized linked lists, or dynamic access stride switching), and use the lab-provided Pin/DynamoRIO tracer script to generate stress_test.champsimtrace.xz:

# Compile your stress test workload
gcc -O2 stress_test.c -o stress_test
# Generate ChampSim trace using the provided tracer script
./scripts/generate_trace.sh ./stress_test -o traces/custom_stress.champsimtrace.xz

Trace Validity & Difficulty Scoring Metrics

To ensure fairness, your submitted trace must satisfy basic validity constraints (to prevent trivial attacks like zero-instruction traces or non-memory instruction loops).

1. Validity Constraints (Filter Rules)

Your trace must meet the following minimum execution bounds when run in ChampSim:

  • Minimum Instruction Count: Must contain at least 20M dynamic instructions (and run smoothly with --simulation_instructions 20000000).
  • Memory Access Density: At least 20% of total instructions must be memory-referencing operations (loads/stores).
  • Address Space Requirement: Memory accesses must span across a footprint of at least 8 MB (exceeding L1D and L2C capacities to force main memory accesses).

2. Difficulty Score Calculation

Each valid trace will be evaluated on the baseline 2-level cache hierarchy across two test runs:

  • Baseline Run: With no prefetcher ("prefetcher": "no").
  • Prefetcher Run: With standard Next-Line or IP-Stride prefetcher ("prefetcher": "ip_stride").

The Trace Difficulty Score (Strace​) is computed as a combination of cache hostility and prefetcher resistance:

Strace​=w1​⋅(1−IPCmax​IPCno_pf​​)+w2​⋅(1−Coverageip_stride​)+w3​⋅Miss RateL2C​

Where:

  • Cache Hostility: Penalizes high baseline IPC and rewards high L1D/L2C miss rates.
  • Prefetcher Hostility: Rewards traces that achieve low prefetcher coverage (Coverage≈0) or induce high useless/late prefetch overhead.

Grading Criteria

Grading for Part 4 is weighted as follows:

  1. Validity Check (Pass/Fail): The trace must pass all minimum instruction count, memory density, and address footprint requirements.
  2. Absolute Difficulty Threshold (60%): Traces that achieve an L2C miss rate >40% or reduce baseline IPC below a designated threshold receive full baseline points.
  3. Relative Leaderboard Ranking (40%): Traces will be ranked by their calculated Difficulty Score (Strace​). The top 15% hardest traces receive top leaderboard marks, with a smooth grading curve applied across the rest of the class.

Design Hints for Hostile Access Patterns

To maximize cache misses and evade prefetching, consider:

  • Pointer Chasing: Random array indexing or non-contiguous node traversal, breaking linear address patterns.
  • Conflict Miss Induction: Accessing addresses that map to the exact same cache set (modulo index alignment) to cause cache thrashing.
  • Stride Deception: Alternating between short predictable strides and sudden large random jumps to trick stride tables into issuing useless prefetches.
  • Thrashing the MSHR: Issuing multiple outstanding misses to unique cache blocks within short instruction windows.
