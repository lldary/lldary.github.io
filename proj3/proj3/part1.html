Part 1: Add Caches in the Configuration Script

In this part, we will extend our configuration with a custom cache hierarchy in ChampSim. Let's start by copying the template configuration file to create your new configuration:

cp lab2_config.json lab3_config.json

In ChampSim, the cache hierarchy and component parameters are specified via a JSON configuration file (e.g., lab3_config.json). ChampSim automatically parses this configuration during the build phase to generate the corresponding C++ source files and headers.

There are several critical parameters that define the geometry and performance of a given cache level (L1I, L1D, L2C, LLC):

  • sets: The number of sets in the cache.
  • ways: The associativity of the cache (the number of blocks/lines per set).

Note: Total Cache Size=sets×ways×block_size (ChampSim's default block_size is 64 bytes).

  • hit_latency: The cycles required to look up tags and access data upon a hit.
  • fill_latency: The additional cycles required when filling a cache line from a lower memory level.
  • mshr_size: The number of Miss Status Holding Registers (MSHRs) to track in-flight misses.
  • rq_size / wq_size / pq_size: The capacity of the Read Queue, Write Queue, and Prefetch Queue.
  • prefetcher: The prefetcher module assigned to this cache (e.g., "no" or "next_line").
  • replacement: The cache line replacement policy (e.g., "lru").

Defining the Cache Hierarchy

Open lab3_config.json and configure the CPU, L1I, L1D, and L2C modules as follows. Be sure to specify "executable_name" so config.sh outputs the correct binary target:

{
  "block_size": 64,
  "cpu": [
    {
      "name": "cpu0",
      "frequency": 4000,
      "l1i": "L1I",
      "l1d": "L1D",
      "l2c": "L2C"
    }
  ],
  "L1I": {
    "sets": 64,
    "ways": 8,
    "mshr_size": 16,
    "hit_latency": 3,
    "fill_latency": 1,
    "prefetcher": "no",
    "replacement": "lru"
  },
  "L1D": {
    "sets": 64,
    "ways": 12,
    "mshr_size": 16,
    "hit_latency": 3,
    "fill_latency": 1,
    "prefetcher": "no",
    "replacement": "lru"
  },
  "L2C": {
    "sets": 2048,
    "ways": 16,
    "mshr_size": 20,
    "hit_latency": 20,
    "fill_latency": 1,
    "prefetcher": "no",
    "replacement": "lru"
  }
}

Calculation Check:

  • L1D Size: 64 sets × 12 ways × 64 bytes = 48 KB
  • L2C Size: 2048 sets × 16 ways × 64 bytes = 2 MB

Building and Running the Simulation

Once you have defined your JSON configuration, generate the C++ modules using config.sh and build the binary:

./config.sh lab3_config.json
make -j $(nproc)

After compilation, run the generated binary (./bin/champsim_proj3) with your target ChampSim workload trace (e.g., gemm.champsimtrace.xz):

./bin/champsim_proj3 --warmup_instructions 20000000 --simulation_instructions 100000000 traces/gemm.champsimtrace.xz

Upon completion, ChampSim outputs detailed statistics directly to standard output (stdout), including IPC, cache hit rates, and MSHR occupancy:

...
=== CPU 0 ===
CPU 0 cumulative IPC: 1.423 Instructions per cycle: 1.423
L1D TOTAL     ACCESS:    1245020  HIT:    1102340  MISS:     142680
L2C TOTAL     ACCESS:     142680  HIT:     118920  MISS:      23760
...
