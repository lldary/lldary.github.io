Archlab gem5 Project 3

Part 1: Custom Cache Hierarchy & Multi-Core Optimization

In this part, you will extend ChampSim with a custom cache hierarchy and explore cache allocation strategies for multi-core parallel execution (multi_run).

Copy the template configuration file to create your working configuration:

cp lab2_config.json lab3_config.json

ChampSim parses a JSON configuration file to set up the memory geometry and auto-generate the underlying C++ source files during the build phase.

1. Single-Core Baseline Setup

Configure lab3_config.json with the following parameters:

{
  "block_size": 64,
  "cpu": [
    {
      "name": "cpu0",
      "frequency": 4000,
      "l1i": "L1I",
      "l1d": "L1D",
      "l2c": "L2C"
    }
  ],
  "L1I": {
    "sets": 64,
    "ways": 8,
    "mshr_size": 16,
    "hit_latency": 3,
    "fill_latency": 1,
    "prefetcher": "no",
    "replacement": "lru"
  },
  "L1D": {
    "sets": 64,
    "ways": 12,
    "mshr_size": 16,
    "hit_latency": 3,
    "fill_latency": 1,
    "prefetcher": "no",
    "replacement": "lru"
  },
  "L2C": {
    "sets": 2048,
    "ways": 16,
    "mshr_size": 20,
    "hit_latency": 20,
    "fill_latency": 1,
    "prefetcher": "no",
    "replacement": "lru"
  }
}

Calculation Check:

  • L1I Size: 64×8×64 B=32 KB
  • L1D Size: 64×12×64 B=48 KB
  • L2C Size: 2048×16×64 B=2 MB
  • Total Baseline Capacity: 2.08 MB

Building and Running the Simulation

Generate the C++ modules using config.sh and build the binary:

./config.sh lab3_config.json
make -j $(nproc)

Run the generated executable (./bin/champsim_proj3) on gemm.champsimtrace.xz:

./bin/champsim_proj3 --warmup_instructions 20000000 --simulation_instructions 100000000 traces/gemm.champsimtrace.xz

2. Multi-Core Expansion & Cache Budget Optimization Task

Setting Up 4 Cores in ChampSim

To evaluate parallel workload behavior (multi_run), ChampSim requires defining multiple core objects inside the "cpu" array and routing their requests to private or shared cache instances.

Below is an example structure configuring 4 CPU cores:

{
  "block_size": 64,
  "cpu": [
    { "name": "cpu0", "frequency": 4000, "l1i": "L1I_0", "l1d": "L1D_0", "l2c": "L2C_0" },
    { "name": "cpu1", "frequency": 4000, "l1i": "L1I_1", "l1d": "L1D_1", "l2c": "L2C_1" },
    { "name": "cpu2", "frequency": 4000, "l1i": "L1I_2", "l1d": "L1D_2", "l2c": "L2C_2" },
    { "name": "cpu3", "frequency": 4000, "l1i": "L1I_3", "l1d": "L1D_3", "l2c": "L2C_3" }
  ],
  "L1I_0": { "sets": 64, "ways": 8, "mshr_size": 16, "hit_latency": 3, "fill_latency": 1, "prefetcher": "no", "replacement": "lru" },
  "L1D_0": { "sets": 64, "ways": 8, "mshr_size": 16, "hit_latency": 3, "fill_latency": 1, "prefetcher": "no", "replacement": "lru" },
  "L2C_0": { "sets": 512, "ways": 8, "mshr_size": 16, "hit_latency": 10, "fill_latency": 1, "lower_level": "LLC", "prefetcher": "no", "replacement": "lru" },
  "...": "Repeat L1I_x, L1D_x, L2C_x for cores 1 to 3",
  "LLC": {
    "sets": 4096,
    "ways": 16,
    "mshr_size": 32,
    "hit_latency": 20,
    "fill_latency": 1,
    "prefetcher": "no", "replacement": "lru"
  }
}

Problem Statement: Fixed Cache Capacity Allocation Strategy

Suppose you are given a fixed total cache capacity budget Ctotal​ (e.g., Ctotal​=8 MB aggregated across all L1, L2, and shared LLC caches for 4 cores).

Ctotal​=all cores∑​(SL1I​+SL1D​+SL2C​)+SLLC​

Where Slevel​=sets×ways×64 B.

When running 4 instances of memory-intensive tasks in parallel (multi_run), design and test different cache allocation strategies under the same total capacity Ctotal​:

  1. Strategy A (Heavy Private L2, Small LLC): Give each core a larger private L2 cache (e.g., 1 MB per core) and a small shared LLC (4 MB).
  2. Strategy B (Lean Private L2, Large LLC): Give each core a small private L2 cache (e.g., 256 KB per core) and devote the remaining budget to a larger shared LLC (6.5 MB).
  3. Strategy C (Varied L1D vs. L2/LLC sizing): Analyze how increasing L1D size (which affects access latency in practice) compares to giving that capacity to L2C/LLC.

Optimization Questions to Answer:

  • How should the fixed capacity budget be split between private caches (L1/L2) and shared cache (LLC) to maximize throughput (total or cumulative IPC across all 4 cores)?
  • What trade-offs arise between private cache isolation and shared LLC capacity utilization during memory-bound workload execution?
